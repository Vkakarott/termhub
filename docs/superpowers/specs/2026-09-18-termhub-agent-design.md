# termhub-agent — design

Date: 2026-09-18. Status: approved in conversation (sections 1–5), written for implementation.

## 1. Why

Today the server reaches machines by SSH (or runs tmux locally). That works on a LAN
but not for a hosted product: the termhub Cloud cannot reach a customer's Mac behind
NAT, and nobody exposes SSH to the internet for us. The landing already promises
"your machines connect to termhub Cloud" — the direction of the connection inverts.

The termhub-agent is a small client the user runs on each machine. It opens **one
outbound WebSocket** to the server and does locally everything SSH did: attach tmux
sessions (PTY), run a fixed set of named operations, and — in the next spec — receive
Claude Code hook events for the "waiting for you" monitor.

Sub-projects agreed: (1) **agent + `agent` transport** (this spec), (2) Claude monitor
and notifications, (3) SaaS (orgs, self-service signup, billing). This spec is
designed knowing 2 and 3 follow.

## 2. Decisions (from brainstorming)

| Question | Decision |
|---|---|
| Language / install | TypeScript in the monorepo (`apps/agent`, npm package `@termhub/agent`); `npm i -g @termhub/agent`. Single binary later. |
| Existing transports | `agent` is added as a third `MachineType`; `local` and `ssh` keep working; UI recommends agent and labels SSH "legado". SSH removal is a future release. |
| v1 surface | PTY + named operations (tmux list/kill/capture, tools detect, hardware, fs list, AI credential, file paste). iOS simulator stays SSH-only; the protocol reserves a `tcp` stream kind for it (v1.1). |
| Enrollment | Token generated by the app when a machine of type `agent` is created. Only the sha256 hash is stored; revocable/rotatable from the machine card. |
| What the server may run | **Only named RPCs.** The server never sends shell text to an agent. |
| Transport shape | Approach A: agent = WebSocket client with a multiplexed binary protocol; server = hub. |
| Privileges on the machine | None beyond the user's own: user-level LaunchAgent / `systemd --user`, no sudo, no ports listening. |

## 3. Protocol (`packages/agent-protocol`)

### 3.1 Connection

- URL: `wss://<server>/agent/ws`. Header `Authorization: Bearer thb_ag_<43 base64url chars>`.
- Invalid/unknown token → server closes with code **4401** before reading any frame.
- Protocol version mismatch → **4409**, reason `protocol`.
- A second connection with the same token replaces the first → the first is closed with **4409**, reason `replaced`.
- Ping/pong every 20 s from both sides; two missed pongs = dead connection.
- Max 64 open stream channels per connection. Max frame 1 MiB, except `file.paste` RPC (20 MiB + 1 KiB envelope).

### 3.2 Frames

Every WebSocket message is binary: `[channel: uint32 big-endian][payload]`.

- **Channel 0 = control**, payload is UTF-8 JSON, one message per frame.
- **Channel n ≥ 1 = stream**, payload is raw bytes (PTY input/output). No envelope.

### 3.3 Control messages

Agent → server:
- `{"type":"hello","protocol":1,"agent_version":"0.1.0","os":"macos"|"linux","arch":"arm64","hostname":"mini","tmux":true,"tools":["claude","gh",...]}` — must be the first message; anything else first → 1008.
- `{"type":"rpc_result","id":"r1","ok":true,"result":{...}}` / `{"type":"rpc_result","id":"r1","ok":false,"error":{"code":"eperm","message":"...","path":"/Volumes/x"}}`
- `{"type":"opened","ch":3}` / `{"type":"open_error","ch":3,"error":{"code":"no_tmux","message":"..."}}`
- `{"type":"closed","ch":3,"code":0}` — the PTY process exited (code = exit code, or null).

Server → agent:
- `{"type":"rpc","id":"r1","method":"tmux.list","params":{}}`
- `{"type":"open","ch":3,"kind":"pty","params":{"session":"th-abc","cwd":"/Users/p/proj","cols":120,"rows":40}}`
- `{"type":"resize","ch":3,"cols":100,"rows":30}`
- `{"type":"close","ch":3}`

Both directions: `{"type":"ping"}` / `{"type":"pong"}` are **not** used — WebSocket-level ping/pong is.

`hello.tools` uses the same list as today's `DETECT_TOOLS` (`tmux claude gh git node pnpm xcodebuild docker adb python3`) plus `wda` when the WDA runner app exists. Server stores `os` and `tools` as `Machine.os` / `Machine.capabilities` (no more polling detect for agent machines).

### 3.4 RPC catalog (v1)

All params/results validated with zod on both sides (schemas live in the protocol package).

| Method | Params | Result | Replaces |
|---|---|---|---|
| `tmux.list` | `{}` | `{sessions: string[]}` | `listTmuxSessions` |
| `tmux.kill` | `{session}` | `{killed: boolean}` | `killTmuxSession` |
| `tmux.capture` | `{session, lines: 1..5000}` | `{text: string}` (plain, no ANSI) | new — base for the monitor |
| `tools.detect` | `{}` | `{os, tools: string[]}` | `machineStatus` |
| `hw.probe` | `{}` | `{stdout: string}` (the same script's output; server keeps the parser) | `collectHardware` |
| `fs.list` | `{path: string}` | `{stdout: string}` (same script output; server keeps the parser) | `browseMachine` |
| `fs.mkdir` | `{parent, name}` | `{path}` | `makeDirectory` |
| `ai.credential` | `{provider: 'claude'\|'chatgpt'\|'gemini'\|'antigravity', config_dir: string\|null}` | `{stdout: string}` (raw credential file text; **parsing and the provider HTTP call stay on the server**) | `readCredential` |
| `file.paste` | `{name: string, data_b64: string}` | `{path: string}` | `saveFileOnMachine` |

`hw.probe`, `fs.list` and `ai.credential` run the **same POSIX `sh` scripts the server uses today**, but the script text lives in the shared package `@termhub/machine-ops` and is embedded in the agent — the server names the operation, it never ships script text. Errors are structured: `{code: 'eperm'|'notfound'|'no_tmux'|'timeout'|'invalid'|'internal', message, path?}`.

Session names match `^[A-Za-z0-9_-]+$` (current `assertSessionName`). Paths must be absolute or `~`/`~/…` (expanded on the machine), no NUL/newline.

### 3.5 PTY stream

`open kind:"pty"` → agent spawns (node-pty) `tmux -u new-session -A -s <session> -c <cwd>` with `TERM=xterm-256color`, `COLORTERM=truecolor`, a UTF-8 `LANG`/`LC_ALL` (same rule as today's `pty-session.ts`), `TERMHUB=1`, and `TERMHUB_TAB_ID`/`TERMHUB_SESSION` set to the session name (the monitor spec relies on these). Bytes flow raw on channel `ch` both ways. `resize` maps to `pty.resize`. `close` from the server kills the PTY (tmux survives). PTY exit → `closed`.

## 4. Server (`apps/server/src/agent/`)

- `connection.ts` — `AgentConnection`: wraps one `ws` socket; frame encode/decode via the protocol package; pending RPC table with per-call timeout (default 8 s; `file.paste` 60 s; `hw.probe` 15 s); channel table; heartbeat. API: `rpc(method, params, timeoutMs)`, `openPty(params, handlers) → AgentPtyChannel {write, resize, close}`, `close(code, reason)`, events `close`. Logs metadata only.
- `registry.ts` — `AgentRegistry`: `Map<machineId, AgentConnection>`; `attach(machineId, conn)` replaces an existing one (4409 `replaced`); `isOnline(id)`, `info(id) → {agent_version, os, tools, connected_at}`, `rpc(id, …)` rejects immediately with `AgentOfflineError` when offline; `openPty`; `disconnect(id, code)`; emits `online`/`offline`.
- `ws.ts` — upgrade route `/agent/ws` registered on the existing upgrade router through a new `router.addPublic(pattern, handler)` that skips cookie auth and the `terminals:read` check (the bearer token is the auth). Flow: parse bearer → `repos.machines.findByAgentTokenHash(sha256(token))` → none: `rejectUpgrade(401)`; else handleUpgrade, wait for `hello` (5 s), validate, `registry.attach`, `repos.machines.touchAgent(id, {version, os, tools})`, and every 60 s while connected `touchAgent(id, {last_seen_at})`.
- `pty.ts` — `AgentPtySession implements PtySession` (interface extracted from today's class: `write`, `resize`, `kill`, `pid: number | null`). `createPtySession(machine, project, tab, size, handlers)` picks `LocalPtySession` (today's class, renamed) for `local`/`ssh` and `AgentPtySession` for `agent`. `terminal/ws.ts` calls the factory; nothing else there changes.
- `screen.ts` — `captureScreen(machine, session, lines)` → `tmux.capture` for agent machines; for local/ssh runs `tmux capture-pane -p -S -<lines> -t =<session>` through `runOnMachine`. Internal only (no HTTP route in this spec).

Named-RPC branches added at the high-level functions (never inside `runOnMachine`): `listTmuxSessions`, `killTmuxSession`, `machineStatus`, `collectHardware`, `browseMachine`, `makeDirectory`, `readCredential`, `saveFileOnMachine`. Each begins with `if (machine.type === 'agent') return …registry.rpc(...)`. A unit test per function asserts that for an agent machine `execFile`/`spawn` is never called.

`runOnMachine`/`runOnMachineWithInput`/`sshBaseArgs` throw `Error('Máquina do tipo agente não executa shell')` when given an `agent` machine, so a missed branch fails loudly instead of silently trying SSH.

The registry is process-local. With blue/green there is one active container; agents pinned to the retiring container reconnect to the new one. Multi-instance routing is out of scope (SaaS spec).

## 5. Agent (`apps/agent`, npm `@termhub/agent`)

### 5.1 CLI

- `termhub-agent connect --url <https://app…> [--token <thb_ag_…>]` — prompts for the token when omitted (never in shell history); performs a real connect + `hello`; on success writes the config, prints the next steps and exits (0.1.1: it used to stay in the foreground, which made users type the next command into the running agent). Re-running replaces the config.
- `termhub-agent run` — connect using the saved config; foreground; what the service runs.
- `termhub-agent status` — prints server, machine name/id, connected/disconnected (with a probe hello — `probe: true` — that the server validates and answers by closing 1000 `probe-ok` without attaching, so the live session is never replaced), version.
- `termhub-agent disconnect` — deletes the local config (revocation happens in the app).
- `termhub-agent service install|uninstall|status` — macOS: `~/Library/LaunchAgents/dev.termhub.agent.plist` (`RunAtLoad`, `KeepAlive` with `SuccessfulExit=false`, which restarts on *any* failure — launchd has no per-exit-code opt-out, so before exiting 78 the agent runs `launchctl bootout gui/$UID/dev.termhub.agent` itself, best-effort, to stop the loop), loaded with `launchctl bootstrap gui/$UID`. Linux: `~/.config/systemd/user/termhub-agent.service` (`Restart=on-failure`, `RestartPreventExitStatus=78`), `systemctl --user enable --now`; prints a note about `loginctl enable-linger $USER` (the only step that may need sudo; never run by the agent).
- `termhub-agent doctor [path …]` — checks: config present, server reachable (a connect + `hello`), tmux found on PATH, node-pty loads, and that each given path (default: `$HOME`, `$HOME/Documents`, `$HOME/Desktop` and every mount under `/Volumes` on macOS) can be listed; an `EPERM` is reported as "Conceda Acesso Total ao Disco a `<process.execPath>` em Ajustes → Privacidade e Segurança → Acesso Total ao Disco". `service install` runs the same path check and prints the note when TCC blocks.

Exit codes: 0 ok; 78 (`EX_CONFIG`) on revoked token (3 consecutive 4401), protocol mismatch (4409 `protocol`) or missing config — systemd stops restarting on 78 (`RestartPreventExitStatus`), launchd is told to stop by the bootout above; 1 otherwise.

### 5.2 Config

`~/.termhub/config.json` (dir 0700, file 0600): `{ "url", "token", "machine_id", "machine_name", "created_at" }`. `TERMHUB_AGENT_HOME` overrides the directory.

### 5.3 Runtime modules

- `client.ts` — outbound WebSocket, sends `hello`, WebSocket ping/pong (answers the server's pings and sends its own every 20 s — one left unanswered by the next tick terminates the socket so the reconnect starts at once), reconnect with backoff 1 s → 30 s (×2, ±20 % jitter), forever; counts consecutive 4401 and exits 78 at 3.
- `dispatch.ts` — routes control messages: `rpc` → handler by method (unknown → `rpc_result ok:false code:'invalid'`), `open` → `pty.ts`, `resize`/`close` → channel.
- `rpc/tmux.ts`, `rpc/tools.ts`, `rpc/hw.ts`, `rpc/fs.ts`, `rpc/ai.ts`, `rpc/paste.ts` — one pure `(params) => Promise<result>` each. Every process is started with `execFile(file, args)`; fixed scripts from `@termhub/machine-ops` run as `execFile('/bin/sh', ['-c', SCRIPT])` — the script text is a compile-time constant, params reach it only through the environment (`P=<path>`) or argv, never string-interpolated.
- `pty.ts` — node-pty per channel; same env rules as the server's local PTY today.
- `service/launchd.ts`, `service/systemd.ts` — render files from templates; `doctor.ts`.

PATH inside the agent: prefix `$HOME/.local/bin:/opt/homebrew/bin:/usr/local/bin` (the same `REMOTE_PATH_PREFIX` the SSH path uses), because the LaunchAgent environment is minimal.

### 5.4 Packaging

`tsc` → `dist/`, `"bin": {"termhub-agent": "dist/cli.js"}`, `"type": "module"`, deps: `ws`, `node-pty`, `zod`, `@termhub/agent-protocol`, `@termhub/machine-ops` (the two workspace packages are bundled into the published tarball via `tsup --noExternal` of those two names, so the npm package has no workspace deps). Node ≥ 20.

## 6. Shared packages

- `packages/agent-protocol` (`@termhub/agent-protocol`): `frames.ts` (`encodeFrame(ch, payload) → Buffer`, `decodeFrame(buf) → {ch, payload}`, throws on < 4 bytes), `messages.ts` (zod schemas for every control message, `PROTOCOL_VERSION = 1`), `rpc.ts` (zod schema per method: params and result; `RPC_METHODS` const; `RpcError` shape).
- `packages/machine-ops` (`@termhub/machine-ops`): moved from the server without behaviour change — `DETECT_TOOLS`, `DETECT_SCRIPT`, `parseDetect`; hardware `SCRIPT` + `parseHardware`; fs `buildScript`/`parseListing` and mkdir script; paste script builder + `safeName`/`sniffImage`; per-provider `credentialScript`s; `SESSION_RE`/`assertSessionName`; `shellQuote`; `REMOTE_PATH_PREFIX`; `UTF8_LOCALE`/`clampSize`. The server modules keep their public API and import from here.

Both packages are plain TS (`tsc`), tested with vitest, added to the root `workspaces` and to `Dockerfile` (`COPY packages/*/package.json`) and CI.

## 7. Data model and API

Prisma (additive, blue/green safe):
```prisma
enum MachineType { local ssh agent }
model Machine {
  …
  agentTokenHash      String?   @unique @map("agent_token_hash")
  agentTokenCreatedAt DateTime? @map("agent_token_created_at")
  agentVersion        String?   @map("agent_version")
  agentLastSeenAt     DateTime? @map("agent_last_seen_at")
}
```
Repository (`repositories/machines.ts`): `findByAgentTokenHash(hash)`, `rotateAgentToken(id, hash)`, `touchAgent(id, {version?, os?, capabilities?, lastSeenAt})`. `Machine` type gains `agent_version`, `agent_last_seen_at` (never the hash).

Token: `thb_ag_` + 32 random bytes base64url (43 chars). Hash: sha256 hex. Generated in `agent/token.ts`.

Routes (`/machines`, `guarded('machines')`):
- `POST /` accepts `type:'agent'` (host/user/port must be absent); response `201 {machine, agent_token}` — the only time the token is shown.
- `POST /:id/agent-token` (`update`) → `{agent_token}`; old hash replaced; open connection closed 4401.
- `GET /:id/status` for agent machines answers from the registry: `{online, tmux, os, capabilities, agent_version, last_seen_at}` without touching the machine.
- `DELETE /:id` also `registry.disconnect(id, 4401)`.
- Simulator routes return `409 'Simulador indisponível em máquinas com agente'` for agent machines.

## 8. Web

- `types.ts`: `MachineType = 'local' | 'ssh' | 'agent'`; `agent_version`, `agent_last_seen_at` on `Machine`.
- `MachineForm.tsx`: type selector with **Agente (recomendado)** first, SSH labelled "SSH (legado)". Creating an agent machine shows the enrollment panel: step 1 `npm i -g @termhub/agent`, step 2 `termhub-agent connect --url <window.location.origin> --token <token>` (copy button; "esse token só aparece agora"), step 3 `termhub-agent service install`, macOS note on Full Disk Access + `termhub-agent doctor`. Below, a live indicator polling `GET /machines/:id/status` every 3 s: "aguardando conexão…" → "conectado ✓ · macOS · agente 0.1.0".
- Machine card: live dot (online/offline), agent version, "visto há X", **Rotacionar token** (confirm) reopening the enrollment panel. Simulator UI hidden for agent machines with "disponível em breve para agentes".

## 9. Errors, reconnection, logging

| Situation | Behaviour |
|---|---|
| Agent offline, tab opened | terminal ws sends `{type:'error', message:'Agente desconectado'}`, closes 1011. |
| Agent drops mid-tab | channel dies → `exit` to the browser, close; web reconnects with its existing backoff; tmux keeps running; `new-session -A` re-attaches. |
| RPC timeout | rejects with `AgentTimeoutError` → route answers 504 `'A máquina não respondeu'`; late result discarded by id. |
| Server restart / deploy | agent reconnects (backoff), re-sends `hello`; no state to restore. |
| Token revoked | 4401; after 3 consecutive the agent logs "token revogado; rode termhub-agent connect" and exits 78. |
| Protocol mismatch | 4409 `protocol`; agent prints the upgrade command, exits 78. |
| Duplicate connection | newest wins; old closed 4409 `replaced`. |
| TCC `EPERM` (macOS) | RPC error `{code:'eperm', path}`; UI shows "sem acesso à pasta — veja Acesso Total ao Disco"; `doctor` reproduces. |
| Malformed frame / unknown channel / > 64 channels / oversize | connection closed 1008; metadata logged; never a crash. |

Logs on both sides: machine id, channel, method, duration, close codes. Never PTY bytes, `tmux.capture` text, credential contents or pasted files.

## 10. Testing

- `agent-protocol`: frame encode/decode (channel 0 vs n, empty payload, truncated), each schema valid/invalid.
- `server/agent`: `AgentConnection` with a fake socket (EventEmitter): hello required first; RPC timeout; unknown id ignored; replacement; channel limit; missed pongs. `AgentRegistry`: online/offline events, offline rpc rejects.
- Server branches: for an `agent` machine each high-level function calls `registry.rpc` with the right method and `child_process` is never touched (spied).
- Agent: RPC handlers with `execFile` mocked (exact argv; invalid session/path rejected); `client.ts` against a real `ws` server on an ephemeral port (hello, reconnect timing with fake timers, exit 78 after 3×4401); service file rendering snapshots.
- End-to-end (one test, runs in CI with tmux installed): Fastify test server + real agent in-process + real tmux (`TMUX_TMPDIR` temp); open a tab over the browser WebSocket, write `echo ok`, read `ok`, `captureScreen` finds it. Simulator excluded.
- Manual checklist (not a gate): LaunchAgent install on the mac mini, TCC prompt on an external volume, `doctor` output.

## 11. Out of scope (next specs)

Claude Code hook events and the "waiting for you" state (monitor spec); HTTP endpoint for `captureScreen`; iOS simulator over the agent (`tcp` channel); device-code enrollment; single-binary packaging; multi-instance registry; orgs/billing (SaaS spec); removal of SSH.
